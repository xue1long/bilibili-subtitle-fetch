# 产物根与代码仓库分离，产物根可指向跨机共享目录

产物（字幕、转录、笔记）原先固定落在仓库内的 `10_raw/`，导致"跨电脑共用同一份下载"只能靠把整个仓库搬进 OneDrive。我们把**产物根**从代码仓库里拆出来，成为一个可配置的独立根（`BILIBILI_SFETCH_RAW_DIR`，未设置时仍为仓库内 `10_raw/`），让两台电脑通过同步盘共用同一份产物，而代码各自本地 clone。

## 考虑过的方案

| 方案 | 否决原因 |
|---|---|
| 整个仓库进 OneDrive | `.venv/` 475 MB、`.chrome-*/` 含登录 cookie、`data/*.db` 是 SQLite，三者都必须排除在同步外 |
| 用 junction 把仓库内的 `10_raw` 指向 OneDrive | **实测**：OneDrive 不跟随 junction 同步目标内容，但**会把 junction 本身同步到云端**，在另一台机器上变成指向该机不存在路径的断链；若那台机器恰好有同名路径则**静默指向错误目录**。跨机路径因此不能用 junction，只能用"配置 + 每机解析" |
| 硬编码 `D:\OneDrive\...` | 同步盘根盘符因机而异（本机 Personal 在 D:，另一台可能是 C:），硬编码必然有一台坏掉 |
| 硬编码盘符 + 每机改配置 | 可行但两台机器配置内容不同，人工同步配置本身就是错误来源。改为存**未展开的** `%OneDriveConsumer%\...`，由进程在读取时展开，同一份配置字符串在两台机器上都成立 |

## 后果

- 产物根下辖的平台编号目录（`01_B站视频转录/` 等）保持不变，单机用户不设环境变量时行为完全一致。
- 仓库内不再保留 `10_raw/`，它由 `.gitignore` 排除，缺失时各 CLI 会自行创建。
- 同步盘上的产物应设为「始终保留在此设备上」：另一台机器读取产物时不应逐个触发按需下载。
- 同步盘根路径一律通过 `%OneDriveConsumer%` 之类的环境变量解析，**任何路径都不得写死盘符**。
