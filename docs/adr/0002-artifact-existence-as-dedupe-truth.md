# 以产物存在性作为跨机去重依据，任务库保持本机私有

任务规划器原先只靠 SQLite 任务库（`data/subtitle_tasks.db`）判断"是否已产出"。两台电脑共用一份产物时，任务库要么各机独立（重复下载），要么放进同步盘（SQLite 锁语义被 OneDrive 破坏，必然 `database is malformed`）。我们让规划器**额外**以产物文件是否存在作为去重依据，任务库退回为本机私有的执行流水。

## 考虑过的方案

| 方案 | 否决原因 |
|---|---|
| 任务库进同步盘 | SQLite 依赖文件锁，OneDrive 会替换文件、锁语义失效，损坏是常态而非意外 |
| 靠 OneDrive 同步延迟"碰运气" | 把正确性押在几秒的同步窗口上；两机紧邻操作时必然重复产出 |
| 索引库进同步盘 | 同一问题，且索引本就定义为可从产物重建的投影（见 `CONTEXT.md` 产物即事实） |

## 后果

- 两台机器写同一个产物根，天然互斥：产物已存在即跳过，无需跨机传状态。
- **已知限制**：被确认为"无字幕"的视频没有产物文件，另一台机器会重跑一次并得出相同结论——只是浪费一次抓取，不产生错误产物。这类"确认无产物"的状态仍只记在本机任务库里。
- **已知限制**：产物刚写完到 OneDrive 同步完成之间存在窗口期，另一台机器此刻规划任务仍可能重复下载一次。
- 规划器新增产物存在判定后，单机行为不变（产物文件存在时本来就该跳过）。
